Two blockers found and fixed this session
-----------------------------------------
1) libhybris hooks gap — __ctype_get_mb_cur_max (bionic-only export; bionic's
   MB_CUR_MAX). Crash signature: SIGSEGV in bionic libc.so file offset
   0x83b28 = __ctype_get_mb_cur_max+8:
       mrs  x8, tpidr_el0
       ldur x8, [x8, #-8]        ; bionic TLS slot tp[-1] — absent on glibc
       ldr  x8, [x8, #0x820]     ; <- faults, x8=0
   Caller (gdb LR 0x7fbed73ce4) = /vendor/lib64/libc++.so locale machinery
   past std::__1::locale::classic() — libc++ initializes the classic locale
   during android_dlopen of any lib importing std::locale (our compat layer
   does via HIDL toString/ostringstream). hooks.c hooks the whole locale.h
   family (newlocale/uselocale/... → glibc) but not this one, so bionic's
   real implementation ran on a glibc thread. Fix: hook it + the *_l family
   (glibc locale_t objects must never reach bionic *_l consumers) + the
   mb/wc conversions. Patch embedded in guest/build-libhybris.sh
   (upstream-able to libhybris/libhybris). After the in-guest rebuild of
   hybris/common: test_dlopen /usr/lib/android/libhwc2_compat_layer.so → rc 0.

2) No binder in the guest — the private-binderfs mount entry never mounted
   (silent, optional) and host binder nodes were never bound in, so
   getService(composer@2.1) blocked forever (12 s silent hang, rc 124).
   mknod replicas (c 489,N) open with ENXIO: binderfs nodes are backed by
   the binderfs superblock instance, NOT the global chrdev map — bind mounts
   are mandatory. Fix in guest/lxc/config:
       lxc.mount.entry = /dev/binderfs/binder    dev/binder    none bind,create=file,optional 0 0
       lxc.mount.entry = /dev/binderfs/hwbinder  dev/hwbinder  none bind,create=file,optional 0 0
       lxc.mount.entry = /dev/binderfs/vndbinder dev/vndbinder none bind,create=file,optional 0 0
   (First failure mode after adding nodes wrongly via mknod was libbinder
   aborting: "Binder driver '/dev/vndbinder' could not be opened. Error: 6".)

3) VISIBILITY: stopping SurfaceFlinger zeroes the panel backlight
   (/sys/class/backlight/panel0-backlight/brightness -> 0), so the first
   passing runs LOOKED black — frames were reaching scanout with the light
   off. This is also why desktop-on always left the panel "dark". Fix:
   force brightness (600) while SF is down, restore after; now in
   guest/hwc-smoke.sh and toggle/desktop-on step 4b.
