# Progress report — 2026-07-01 (day one)

From design spec to flash-day-ready in one session. Everything below is
committed; nothing has been flashed to the phone yet (no USB cable).

## Done

**Repo built from the spec** (`docs/design-spec.md`): recon tooling, kernel
fragment + build system, boot repack flow, Magisk module, Debian/LXC guest
builder, the §4 toggle scripts (desktop-on / desktop-off / cycle-stress), the
`evgrab` EVIOCGRAB input-handoff daemon in C, and the `./det` host helper.

**Device recon completed** over wireless adb (`docs/recon-findings.md`):

- Phone is crDroid 12.10 / Android 16 — not stock (fingerprint spoofed to
  A12). Kernel 4.14.357-openela from crDroid's sm8150 fork.
- Composer HAL is HIDL 2.1–2.4 with QTI gralloc/mapper 4.0 → the well-trodden
  libhybris gralloc4 pairing. GPU-acquisition risk assessed low.
- binderfs already in the kernel → guest binder plan simplified to a private
  binderfs instance (extra-binder-devices approach dropped).
- Kernel misses PID_NS, IPC_NS, USER_NS, CGROUP_DEVICE, CGROUP_PIDS,
  POSIX_MQUEUE → exactly what `kernel/determination.config` adds.
- DP-alt / DisplayPort out confirmed working on this ROM (user-verified) —
  §5 external convergence has no remaining hardware risk.

**Kernel built**: crDroid `16.0` tree, config based on the *running* kernel's
`/proc/config.gz` (guaranteed parity) + our fragment, merge verified
option-by-option before compiling. Distro clang 22 + extracted Arch aarch64
binutils, no root needed on the host. **3m13s** wall time on the 5600X.

**Flash package assembled and verified**:

- `boot_b` dumped from the device (pristine copy kept in `artifacts/` as the
  restore image), repacked with our kernel via magiskboot v30.7 (matches the
  phone's Magisk), kernel-inside verified as our build, cmdline preserved →
  `boot/determination-boot.img`.
- Magisk module zip with static aarch64 `evgrab` (cross-built from extracted
  Arch gcc/glibc; host-arch build functionally tested against real evdev
  nodes, including correct abort-on-busy behaviour).
- Boot-time desktop-off: stale desktop-mode state from a reboot/panic is
  cleared in post-fs-data, so every boot starts in phone mode.
- Runbook: `docs/flash-day.md` (RAM-boot first, A/B fallback, EDL last resort
  — no hard-brick path).

## Friction encountered (all resolved, all documented in AGENTS.md)

Distro `android-tools` adb has broken wireless pairing (use official
platform-tools, persisted at `~/platform-tools`); `adb root` drops wireless
transports (recon.sh now prefers Magisk su); Magisk's Shell superuser toggle
was off, denying silently; wireless port rotates on every toggle/reboot.
